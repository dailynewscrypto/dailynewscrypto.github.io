Why bridged tokens can show different balances

A bridged token can show a different raw balance because decimals set display units; learn the conversion, rounding limits and checks that keep transfers clear.

Crypto Daybook NewsroomSep 30, 20262 min read

A bridged token can show a different raw balance from its original because each token’s decimals set how its smallest units appear on screen. The displayed balance is a formatted view of an integer recorded by the contract, not a separate amount stored as a decimal number.

That distinction matters when you compare tokens across chains or enter a transfer. For a separate example of a wrapped asset, see how ZeroFi wraps XMR on Sepolia. The same basic question applies: what unit does the token contract count?

What do token decimals mean?

Decimals tell a wallet how many places to move the decimal point when it displays a token balance. ERC-20’s decimals field is optional metadata for user interfaces; it does not change how the contract adds, subtracts or transfers balances.

For example, a token with 6 decimals represents 1 token as 1,000,000 base units. A balance of 12,345,678 base units displays as 12.345678 tokens. If the same integer belonged to a token with 18 decimals, it would display as 0.000000000012345678 tokens. The raw number alone cannot tell you the human-readable balance. You also need the token’s decimals.

Why can a bridged token show a different balance?

A bridge moves value between networks by using contracts that lock and release tokens, or burn and mint representations. The destination token may use a different number of decimals from the original. The bridge must then convert amounts so the destination units represent the intended value.

Suppose an original token has 6 decimals and its bridged version has 18. To represent 1 original token, the destination contract could record 1,000,000,000,000,000,000 base units. The raw integers differ, but both display as 1 token. This is a change in unit scale, not proof that the bridge created extra value. Bridge designs and conversion rules vary, so check the specific token contracts and bridge details.

Conversions can also leave a remainder when the destination uses fewer decimals. A contract cannot record a fraction smaller than its smallest unit, so it may round down or reject an amount that does not fit. The leftover fraction is often called dust.

How can you check a bridged token balance?

Check the contract and its decimals on the network where the token sits. Then compare the displayed amount with the contract’s raw balance using that decimals value. A wallet’s label or ticker alone cannot confirm that you are viewing the intended token.

  • Confirm the network and token contract address.
  • Read the token’s decimals value; ERC-20 does not require every token to provide it.
  • Convert the raw balance by dividing it by 10 raised to the decimals value.
  • When transferring across chains, follow the bridge’s conversion and minimum-amount rules.

Use the destination token’s decimals when reading its balance or preparing a transfer on that chain. Use the source token’s decimals for the original. If the numbers seem far apart, compare the formatted amounts and the bridge’s conversion rule before concluding that the balance is wrong.
