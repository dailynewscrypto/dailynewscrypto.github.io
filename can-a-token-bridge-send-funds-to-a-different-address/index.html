Can a Token Bridge Send Funds to a Different Address?

A token bridge can send funds to a different destination address when its transfer flow allows it, but that address must work on the receiving chain.

Crypto Daybook NewsroomOct 5, 2026 · 01:11 UTC3 min read

Yes, a token bridge can send funds to an address different from the one that starts the transfer, if the bridge offers a recipient field. The transfer still depends on the address recorded for delivery on the destination chain. If the bridge does not let you choose one, it will usually send funds to the connected wallet address.

How does a bridge choose the receiving address?

A bridge records a destination address as part of the transfer request. It then locks or burns tokens on the source chain and arranges for tokens to be released or created on the destination chain for that address. The exact steps vary by bridge. For Polygon’s withdrawal paths and how the exit models differ, see the fuller Polygon Bridge guide.

Some bridge screens fill in the connected wallet by default. Others let you enter a separate recipient. Check the destination address before signing: after the source-chain transaction is confirmed, the bridge may not offer a way to change where the funds go.

Can the destination address belong to another wallet?

Yes. You can often send to someone else’s address, or to another wallet you control. The address must be usable on the destination network and able to receive the asset. On networks that use the same address format, the same string can appear on both chains, but it does not prove that the same person controls it on each one.

Before you start, check these details:

  • The selected destination network is the one the recipient uses.
  • The address belongs to the intended person or account on that network.
  • The bridge supports the token and destination you selected.
  • The recipient can access the token there, including any needed wallet or contract support.

What if the bridge does not offer a recipient field?

Then the transfer may be limited to the connected wallet. One option is to bridge to that wallet first, then send the tokens to the other address in a separate transaction on the destination chain. That adds a step and a network fee, but makes the recipient clear before you send.

For a transfer straight to a contract or an exchange deposit address, confirm that the service accepts bridged deposits and the specific token on that network. A valid-looking address alone does not guarantee the recipient can credit or return the funds.

The practical rule is simple: use a bridge with a recipient field when you need delivery to a different address, and verify the address and network on the final review screen. If there is no field, assume the connected wallet receives the funds.
