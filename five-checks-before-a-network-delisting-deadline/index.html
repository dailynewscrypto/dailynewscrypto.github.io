Five Checks Before a Network Delisting Deadline

Before an exchange stops supporting a network, confirm the deadline, token contract, withdrawal route and test transfer so funds do not land on the wrong chain.

Crypto Daybook NewsroomOct 4, 20263 min read

Before a network delisting deadline, confirm which service is ending support, the exact cutoff, and how your asset can move afterward. A delisting can stop deposits, withdrawals, trading, or some combination of the three. The right steps depend on what the notice says, so read the full announcement before moving funds.

What exactly is being delisted?

Check whether the exchange is removing a network, a token, or a trading pair. These changes have different effects. If an exchange stops deposits on one network but keeps withdrawals open for a set period, you may still be able to move tokens out after deposits end. If it removes a trading pair, the token may remain available on another pair or service.

Look for the asset name, network name, and any token contract address in the notice. A contract address identifies a token on a particular network. Names and tickers can match across networks, but the tokens may not be interchangeable. For a cross-chain transfer, read Rango Bridge’s guide to a first cross-chain swap for more detail on how the route works. Confirm that the exchange and receiving wallet support the same asset and network before sending.

When does each service stop?

Record the deadline for each action separately. An exchange may set different times for deposits, trading, and withdrawals. Check the time zone, too: a cutoff listed in UTC may fall on the prior date where you live. Do not assume that a token becomes withdrawable until the last minute; network congestion or exchange processing can delay a transfer.

Before acting, make a short checklist:

  • Deposit cutoff and whether new deposits will be credited.
  • Trading cutoff and any open orders you may need to cancel.
  • Withdrawal cutoff and any stated fees or minimum amounts.
  • Supported destination networks and wallet addresses.

Where can the token go afterward?

Check the receiving wallet or service directly. It must support the same token on the same network. A wallet that shows one version of a token may not support another version with the same ticker. If the project has announced a migration, follow its official instructions and verify the contract address there. Do not rely on a search result or an address copied from an unsolicited message.

Should you test the transfer first?

When the exchange permits it, send a small test amount before moving the rest. Confirm that it arrives at the intended destination and that you can access or use it there. A test costs time and may involve a fee, but it can expose a wrong network or address before a larger transfer. Keep the transaction record until the funds appear in the destination wallet.

The safest plan is to act early, use the exact network named by both sides, and keep a copy of the exchange notice. If there is no supported destination or the instructions conflict, contact the exchange or project through its official channel before sending.
